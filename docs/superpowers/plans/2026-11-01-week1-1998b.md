# Week-1 LEDES 1998B implementation plan

> **For agentic workers:** Use superpowers:executing-plans for inline execution. No commits or publication are authorized.

**Goal:** Build a local, lossless field parser and safe canonical builder with independent golden fixtures.

**Architecture:** One TypeScript package. Store every field as a string so identifiers, decimal scale and empty values survive. Parse recoverable content with diagnostics, but return no records when the structure is ambiguous. Build only printable ASCII fields with exact headers and CRLF records.

**Tech stack:** TypeScript 6.0.3, ES2022, Node's test runner. TypeScript is a development dependency only.

**Spec:** the project handover notes, kept outside this repository, sections 6–7. Field definitions: LOC 1998B workbook revision July 2014, downloaded on 2026-11-01.

## Global constraints

- Working directory: the repository root, approved by the user on 2026-11-01.
- Working name `billcheck`, library name `ledes`. Final brand and domain remain undecided.
- One TypeScript package with zero runtime dependencies.
- No runtime imports or Node globals in the library. Target Node, Bun, Deno and Workers.
- Week 1 covers parser and builder only. Dates, amounts, required values, totals, UTBMS and client rules belong to later validation.
- No LOC error descriptions. Structural diagnostics use original wording and project-owned identifiers.
- No commits, public repo, npm publication, new outreach or spending.

## Review focus

- Preserve decimal precision, leading-zero IDs, empty values and field whitespace.
- Reject displaced headers and malformed rows without returning a silently incomplete invoice.
- Report non-ASCII input without replacing characters or guessing byte encodings.
- Reject builder delimiter injection, control characters, missing fields and unexpected fields.
- Preserve multiple invoices and invoice adjustments without imposing one-invoice assumptions.
